实证：固定摘要的 ARM64 Linux 6.18.52 与 runc v1.5.2；三组自建容器的五组内核能力掩码、原始套接字允许/拒绝、子进程继承；通过静态预检的受限 OCI exec 配置在内核中不能创建原始套接字；直接调用 runc 的合成宽松 OCI exec 配置可重新授予 `CAP_NET_RAW`。本项目的策略预检会拒绝这份宽松 exec 配置。VM 实验没有调用 `run-exec` CLI。完整机器回执和串口日志在 `Build/验证/ContainerCapabilityDropGate-20261006`。

推断：在可信管理员确保创建配置确实用于运行中容器、记录与容器 ID 相符且受 root 保护、策略和 bundle 不可被替换的自有工作流中，白名单可防止意外多授予能力。工具没有受控创建入口，不能单独鉴定创建记录与运行中容器的关系；生产接入、权限隔离及竞态需单独审核。`run-exec` 不能委托给低权限用户以自选参数调用。
